# Intake Questions

Used by the planner in **intake mode**, at the start of a new project, to fill in `docs/project-context.md`.

## How to run intake

1. Ask in **3 rounds**, max 6 questions per round. Wait for answers between rounds.
2. Accept short answers. If the user says "skip" or "don't know", write `[TBD — skipped]` and move on.
3. If the user shares a link (old site, Instagram, brand guide, reference sites), read it and **propose** answers instead of asking — the user just confirms or corrects.
4. After round 3, write `docs/project-context.md`, set `Status: intake done`, and show the user a short summary.
5. Only when the user confirms, set `Status: confirmed by user`. Foundation does not start before that.

Required before Foundation (cannot be skipped): brand / site name, what it sells, primary audience, main conversion action, at least one site goal, primary color or "let the designer propose", the page list.

---

## Round 1 — Business & goals

1. What is the brand / site name, and what does it sell or offer?
2. Who is the main customer? (age, location, what they care about)
3. Which countries or cities, which languages, which currency?
4. What should a visitor *do* on the site? (book, buy, call, fill a form, WhatsApp, visit a store…)
5. Top 3 goals for the site, in order.
6. Is there an existing website or social account to look at? (links)

## Round 2 — Brand

1. Do you have a logo and brand guide? (files or links)
2. Brand colors (hex if known) — or should the designer propose a palette?
3. Fonts — or should the designer propose?
4. Tone of voice in 3 words. Any words to always use or never use?
5. 2–3 websites you like the look of, and what you like about each.
6. Photography: do you have photos, or will we use stock / placeholders?

## Round 3 — Pages & setup

1. Which pages do you need at launch? Which can come later?
2. Integrations: email/CRM, analytics, ad pixels, booking or payment tools?
3. Forms: what should each form collect, and where should submissions go?
4. Is this replacing an old site? (old URLs that need redirects)
5. Who approves go-live (merges PRs)? Who owns the content?
6. Any deadline, budget limits for paid services, or hosting preference?
